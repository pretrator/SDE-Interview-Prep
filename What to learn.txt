    1. Feature Development
        What to be mindful of 
            -> Realiable Feature
                Meaning of reliability -> 
                    Hard limits of failures and executions
                
                Ways to achieve reliability
                    1. Validate the inputs/params of a function and ensure they are under the specified limits
                    2. Ensure output is also under a specified limits 
                    3. Handle / Raise all possible errors
                    4. Ensure all possible variable achieving nulls are handled out
                    5. Ensure every line is under specified set of limits
                    6. Easy to Debug under Fire

            -> Scalable Feature (Scalability)
                -> It should not change its Behaviour when used by 1 or 10 or a million users
                -> Most of it is handled under High level design

            -> Maintainability
                -> Operations to keep it running as is
                -> As time passes expectations changes, we need to meet our new expectations without having deep code changes


            -> Extendability
                -> Degree of Extendability
                -> People expect infinite degree of Extendability
                -> Use Common Sense - 
                -> How -> 
                    Pick n things
                    Crystalline their behaviours
                    Bring all similiar behaviour entities under single umbrella
                    Now that Umbrella(Class) can be used to extend to any new addition behaving similiarly

                The Caveats
                    -> There is always a higher degree of extensibility in a given system
                        - It is the job of dev to choose to move system up or not
                        - Every degree of extensibility introduces higher degree of complexity 
                            -> Higher degree of complexity introduces exponential increase in the number of interacting entities
                        - We always aim for highest degree of extensibility which is manageable and handles common sensical Extension
                    -> Unification reduces the degree of complexity so unification should always be hand in hands with Extendability
                    -> In interviews 
                        -> If you have built a system with k degree of extensibility 
                        -> Interviewer will generally ask you to tell him how can we achieve k + 1 degree of Extendability
                        -> Need to answer and prepare for this type of qustions
                            -> cause they generally incur panic
            -> Readability
                -> Should not be hard to understand the written structure
                -> At best single go through should be enough 
                -> This will affect the new dev reading the old codes

            -> Simplicity
                -> No complicacy
                -> Do single thing in single line
                -> Simple things are easy and fast to understand
                -> Best code look like a poetry
